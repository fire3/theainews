Ruby on Rails 之父、37signals 联合创始人、Omarchy 操作系统作者 David Heinemeier Hansson（DHH）在最近一期 Lex Fridman 播客（时长超过 5 小时）中再度谈编程与 AI。他透露，过去两个月开发 Omarchy Linux 最新版本 Quattro 期间，自己没有亲手写过任何一行最终上线的代码：代码全部交给 AI Agent 完成，他负责审查架构、检查关键代码，并告诉 AI 自己想解决什么问题。他干脆地形容，自己「已经变得可有可无」。

## 两个月零手写代码，Agent 加速比例接近 100%

DHH 把过去这段时间划分为几个阶段：2025 年 11 月 24 日之前是「前智能体时代」，AI 只是查资料、碰撞想法的助手，没有真正改写他的工作方式；转折点是 11 月底的 **Opus 4.5**——他布置了几项任务后发现，模型输出的 Ruby 代码质量几乎和自己手写别无二致。到圣诞节前后，大量开发者开始被 Agent 的体验震撼；今年初春子智能体（Sub-Agents）出现后，大型任务被拆解，效率提升 5 到 10 倍，8 个子智能体可以并行干活；而到了今年夏天，随着 **Opus 5、Fable、Sol（GPT-Sol）** 等模型问世，「我不再需要告诉它具体去往何方，只要抛出问题，它就会规划路线、给出方案」。

「我依然会去看结果，因为我好奇心很强。但在决定代码怎么写、选择实现路径这件事上，我已经变得可有可无。」DHH 以 Quattro 为例：这个版本最终发布的代码「没有一行是我亲手写出来的」；他审查过系统整体架构和模型层关键代码行，但有相当一部分 UI 代码和辅助代码他从未看过。他把这种信任比作 GPS 导航的演进——「它不会做出愚蠢操作，就算出错，也拥有自我修复能力」。

## 大公司软件为何没有爆发式迭代

被问及为什么成熟软件（如 Photoshop）没有借 AI 迎来功能爆发，DHH 认为瓶颈不在编码实现，而在人力与沟通成本：产品经理、设计师、部门 VP、CTO 层层参与，生产力在流程中消耗殆尽。「想要拿到 10 倍、100 倍，极少数情况下甚至 1000 倍的生产力提升，你必须直接和 Agent 交互，不能再经过一层人类中转。」

他还点出另一层：大多数组织其实不知道自己想要什么，「瓶颈并不在于怎么实现，而在于想法、愿景和品位」。他举例说，微软拥有几乎无限的编程能力数十年，但「能写出大量代码，不代表就能做出真正优秀、真正有吸引力的软件」。

## 计算平台重新进入竞争：Linux 的窗口期

DHH 认为，桌面计算平台大约 40 年来第一次真正重新进入竞争状态。Linux 从 1991 年存在至今，早已「占领」了服务器、Android、家电等几乎所有角落，唯独没有攻下桌面电脑；而 AI 时代给了他突破口——「如果有一款软件把你牢牢绑定在 Windows 上，现在你完全有能力亲自把它重新写出来。」他相信一个人就能在 Linux 上重做 Premiere 或 Photoshop 级别的软件，哪怕只覆盖自己需要的「那 5%」。

在他看来，Linux 那些曾被当作缺点的特性——晦涩的配置文件、奇怪的报错信息——反而可能成为 **Agent 操作系统**最理想的基础；而苹果精心策划的封闭体验，对 Agent 与开发者而言「充满敌意，到处都是限制和围墙」。他还提到，Linux 内核的 AI 贡献数量曲线「是一条明显的抛物线」，Linus Torvalds 本人几周前也撰文明确欢迎 AI，「你完全可以 fork 自己的版本，因为我们就是要使用 AI」。

Omarchy 的设计目标也与此相关：不是做一个「山寨 Windows 或山寨 Mac」，而是打造一台可任意塑造、面向 Agent 的操作系统。DHH 透露，Quattro 发布后已有数万人下载；插件市场三天内涌入 330 款插件，用户可以基于内置插件改写操作系统 UI 与功能。

## 开源与氛围式编程

面对开源社区关于「AI 生成代码是否污染项目」的巨大争论，DHH 的态度是：这恰恰是开源愿景的实现——「人人都可以参与贡献」。他以 25 年开源经验断言「大多数程序员的水平其实挺差」：不写注释、不写单元测试、提交 PR 时说不清来意；而 Agent 只要你告诉它怎么做，就会认真地执行。过去三个月开发 Quattro 期间，他合并了超过 1000 个 Pull Request，其中相当一部分来自「传统意义上并不是程序员」的人，并且他已经不再逐一审查 PR，而是让 Agent 先行筛选、汇总，「我只需要决定：合并，还是不合并」。

关于「氛围式编程（Vibe Coding）」，DHH 坚持把它和编程严格区分：氛围式编程是「告诉智能体去构建软件，但不去看底层实现」，因此实践它的人不算程序员。他甚至认为，自己懂太多编程知识一度反而成了劣势——「你会按照自己习惯的方式告诉 Agent 该怎么做，而它又非常擅长执行」，更好的方式是描述想要的结果。他由此得出更激进的观点：在智能体工程上，优秀程序员未必比非程序员做得更好，「软件开发本质上就是产品管理」。

他还披露，自己意外地成了「多语言程序员」：过去两个月里用 Agent 写了 C++、Rust，并为 Quattro 交付了三款正式应用。其中写作应用 Omawrite 大约 20 分钟就有了第一个版本，两天后他就彻底抛弃了 Typora。他形容自己极其讨厌阅读 Rust 代码——「就像往眼睛里泼酸水」，但也承认「Rust 作为面向智能体工程的平台堪称完美」。

## 给程序员的建议

对于程序员的普遍焦虑，DHH 给出二分法：如果你热爱的只是拼接逻辑语句这类机械编码，这份工作确实受到威胁；如果你真正热爱的是构建事物，「你非但不会被威胁，反而大有可为」。他引用「杰文斯悖论」与 ATM 的类比——成本下降、需求上升——来论证 AI 会催生更多软件需求，岗位未必减少；同时他也承认，被裁员的个体痛苦是真实的。

他对年轻程序员的建议是：不要试图预判未来，「就算行业最聪明的人，也无法预测两代模型迭代之后世界会是什么模样」；专注当下，亲身接触当前最顶尖的技术。「你不会错过什么」是他这个时代最大的感悟——就算徒步旅行一年脱圈，回来只要两周就能跟上最前沿。他还提到，公开构建与开源社群能带来同伴情谊，对抗个人的存在主义焦虑。

在访谈末尾，DHH 谈到自己现在「编程所使用的语言已经变成了英语」——过去三个月他用自然语言指挥 Agent 写程序，「如果说世界上还有哪种编程语言比 Ruby 更美，那就是英语」。至于 OpenAI、Anthropic 会不会杀进操作系统赛道、开出巨额支票来收购，他的回答是：「我真的不需要钱」，可以纯粹为了乐趣与清晰的愿景去做这件事，即便 Omarchy 最终只是历史上一个注脚，「那也完全没关系」。

## 核心总结

- DHH 在 Lex Fridman 播客中表示，过去两个月开发 Omarchy Quattro 期间没有手写过任何一行上线代码，Agent 加速比例接近 100%，他「已经变得可有可无」
- 转折点是 2025 年 11 月的 Opus 4.5；此后经子智能体、Opus 5 / Fable / Sol 等阶段，AI 从辅助走向完全接管
- 他认为组织与软件迭代的瓶颈在于人力沟通、愿景与品位，而非编码本身；要拿到 10 倍至 1000 倍生产力，必须直接与 Agent 交互
- 他判断 Linux 极可能最终统治桌面端：Agent 天生适合 Linux，一个人就能重做 Premiere、Photoshop，Omarchy Quattro 已有数万人下载、三天涌入 330 款插件
- 他支持开源社区拥抱 AI 生成的 PR，让 Agent 先行筛选，「大多数程序员水平挺差」
- 对程序员的建议：机械编码受威胁、构建者大有可为；不要预判未来，专注当下，公开构建以对抗焦虑
